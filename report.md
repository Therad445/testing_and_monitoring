# Report

## 1. Доработки сервиса

В сервис была добавлена обработка следующих проблемных ситуаций:

1. Модель не загружена при старте сервиса:
   - приложение продолжает работать;
   - `/health` и `/predict` возвращают корректную ошибку 503.

2. В `/predict` передан невалидный вход:
   - лишние поля запрещены;
   - для числовых полей добавлены базовые ограничения;
   - FastAPI/Pydantic возвращают 422.

3. В запросе отсутствуют фичи, необходимые текущей модели:
   - в `to_dataframe()` добавлена явная проверка missing features;
   - сервис возвращает 422 и список отсутствующих признаков.

4. Передан невалидный `run_id` в `/updateModel`:
   - сервис возвращает 400;
   - предыдущая модель остаётся активной;
   - ошибка логируется;
   - в метриках фиксируется неуспешное обновление.

5. Ошибка во время инференса:
   - исключение перехватывается;
   - сервис возвращает 500;
   - ошибка отражается в технических метриках.

Добавлены тесты на:

- функции предобработки данных;
- missing / unknown features;
- успешный инференс модели;

## 6. Evidently

Реализовано накопление входных данных и предсказаний в памяти сервиса.
Первые `DRIFT_BATCH_SIZE` событий используются как reference dataset.
Далее каждые `DRIFT_BATCH_SIZE` новых событий формируется current dataset, строится отчёт `DataDriftPreset`, после чего он отправляется в Evidently workspace.
