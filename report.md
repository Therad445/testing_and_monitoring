# Report

## 1. Доработки сервиса

В сервис были добавлены проверки и обработка проблемных ситуаций.

Обрабатываются следующие случаи:

1. Модель не загрузилась при старте приложения. В этом случае `/health` и `/predict` возвращают корректный код `503`.
2. В `/predict` пришёл невалидный запрос. Для числовых полей добавлены базовые ограничения, лишние поля запрещены, ошибки валидации возвращаются как `422`.
3. В запросе отсутствуют признаки, которые требуются текущей модели. В `to_dataframe()` добавлена явная проверка missing features, сервис возвращает `422` и список отсутствующих полей.
4. В `/updateModel` передан невалидный `run_id`. Сервис возвращает `400`, предыдущая модель остаётся активной, ошибка логируется.
5. Во время инференса произошло исключение. Ошибка перехватывается, сервис возвращает `500`, информация попадает в технические метрики.

## 2. Тесты

Добавлены тесты на:

* преобразование запроса в DataFrame;
* missing / unknown features;
* успешный `POST /predict`;
* обработку ситуации, когда модель не загружена;
* `POST /updateModel` с невалидным `run_id`;
* доступность `/metrics`.

По итогам запуска тестов: `8 passed`.

## 4. Дашборды

В Grafana собран дашборд по четырём блокам:

1. технические метрики сервиса;
2. метрики, связанные с входными данными;
3. метрики работы модели;
4. информация о текущей модели и её обновлении.

На дашборде есть панели для числа запросов, времени ответа, 5xx ошибок, времени предобработки, распределения признаков, времени инференса, распределения вероятностей и классов, текущего `run_id`, типа модели и списка нужных фичей.

## 5. Алерты

В Grafana настроены alert rules:

1. `High service latency`
2. `High inference latency`
3. `5xx detected`
4. `High memory usage`
5. `Prediction skew`
6. `Failed model update`

Уведомления отправляются в Telegram-чат через contact point в Grafana.

## 6. Evidently

Для контроля drift реализовано накопление входных данных и предсказаний в памяти сервиса. После накопления reference/current батчей строится отчёт `DataDriftPreset`, который отправляется в Evidently Workspace.

В проекте Evidently появляются новые отчёты во вкладке `Reports`, что подтверждает корректную отправку результатов drift-monitoring.

## 7. Итог

Сервис поднимается на VM, отвечает на `/health`, `/predict`, `/updateModel` и `/metrics`, внешний Prometheus скрапит метрики, дашборд и алерты в Grafana настроены, уведомления приходят в Telegram, отчёты Evidently формируются и сохраняются в проекте.
